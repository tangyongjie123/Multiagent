# RepoGraph 项目需求

更新时间：2026-11-03

## 1. 产品定位

RepoGraph 是一个面向研发团队的 Git 仓库静态审查平台。用户提交公开仓库地址后，平台通过多个专业 Agent 分析仓库结构、架构、测试、安全与代码质量，生成可定位、可追溯、可下载的中文审查报告。

产品重点不是代替编译器和完整 SAST，也不是自动修改代码，而是在早期快速给出有证据的工程风险清单，并提供后续扩展为知识图谱和代码检索平台的基础。

## 2. 目标用户

- 需要快速了解陌生开源项目的开发者。
- 提交课程设计、毕业设计或面试项目前希望自查的开发者。
- 需要统一代码审查入口的小型研发团队。
- 希望基于多 Agent 和 RAG 继续做二次开发的研究人员。

## 3. 核心用户流程

1. 用户在 Web 页面输入公开 Git URL，可选填写分支。
2. 主 Agent 创建分析任务并进入克隆阶段。
3. 系统浅克隆仓库并扫描结构，不执行仓库内的代码或命令。
4. 主 Agent 依次调度六个专业 Agent。
5. 各 Agent 返回结构化结果与问题列表。
6. 主 Agent 汇总、去重并生成 Markdown 报告。
7. 前端实时展示执行过程、问题、报告与历史记录。
8. 用户可在运行结束前取消任务，也可重新分析同一仓库。

## 4. 产品范围

### 4.1 MVP 范围

- GitHub、GitLab 和 Gitee 的公开 HTTP/HTTPS 仓库。
- 指定分支浅克隆。
- Java、Spring Boot 和 Maven 项目优先，同时识别常见语言与构建文件。
- 基于目录扫描、确定性规则和 LLM 推理的静态分析。
- 架构、测试、安全、质量四类问题。
- critical、major、minor、info 四级严重程度。
- PostgreSQL 持久化、LangGraph checkpoint、SSE 实时事件。
- 中文 Web 控制台、Markdown 报告查看与下载。

### 4.2 暂不包含

- 私有仓库和需要登录的 Git 服务。
- 执行被审查仓库的构建、测试、脚本或程序。
- 自动修复、提交或推送代码。
- 完整编译器数据流分析、符号执行和动态污点分析。
- 公开 SaaS 多租户、计费、组织权限和审批流。
- 面向大型单体仓库的增量索引和分布式任务调度。

## 5. Agent 需求

| Agent | 必须完成的工作 |
| --- | --- |
| Main Agent | 创建任务、选择下一步、汇总结果、处理失败和终止 |
| Repository Agent | 文件统计、语言识别、构建文件、测试文件、入口类和 Spring 标识 |
| Architecture Agent | 识别技术栈、模块、分层、依赖和架构风险 |
| Test Agent | 识别测试文件和框架，指出测试缺口 |
| Security Agent | 检查疑似凭证、私钥、命令执行和基础安全反模式 |
| Quality Agent | 检查异常处理、日志、可维护性和确定性问题 |
| Report Agent | 汇总证据、严重级别和建议，生成中文 Markdown |

约束：

- 每次运行必须有且只有一个主 Agent。
- 子 Agent 只能由主 Agent 调度。
- 主 Agent 只能选择 LangGraph 中声明的合法动作。
- 任一关键 Agent 失败时不得把任务标记为成功。
- Agent 输出必须使用结构化 Schema，不得只返回不可校验的自然语言。

## 6. 功能需求

### FR-01 仓库提交

- 接受公开 Git URL 和可选分支。
- 拒绝 `file://`、SSH、包含用户名密码的 URL 和不在白名单中的主机。
- URL 校验失败返回明确的中文错误。

### FR-02 安全克隆

- 使用浅克隆和单分支模式。
- 设置克隆超时、仓库体积和文件数量上限。
- 克隆失败或超时时释放子进程。
- 工作目录按分析 ID 隔离。

### FR-03 仓库扫描

- 跳过 `.git`、依赖目录、构建产物和软链接。
- 统计语言、构建文件、测试文件、入口点和 Spring Boot 标识。
- 限制源码文件数量与单文件读取字符数。
- 扫描结果作为 Repository Agent 产物保存。

### FR-04 专业分析

- 确定性规则必须先运行，结果可复现。
- LLM 分析必须接收有限源码摘要，不能默认发送完整仓库。
- 每条问题包含分类、严重级别、标题、位置、证据、影响和建议。
- 无文件级位置时允许使用项目级问题，但必须说明证据来源。

### FR-05 编排与异常处理

- 分析状态为 `pending`、`cloning`、`analyzing`、`completed`、`failed` 或 `cancelled`。
- 主 Agent 决策和 Agent 事件写入 PostgreSQL。
- 失败任务保留失败信息，不生成“成功”报告。
- 心跳超时的中断任务由启动恢复逻辑标记为失败。
- 用户取消后终止正在运行的 Git 子进程。

### FR-06 实时展示

- 前端通过 SSE 接收状态和事件。
- 页面显示仓库、当前 Agent、耗时、问题数量与 Commit。
- 问题支持按严重级别筛选。
- 页面使用环形图和分类条形图展示问题分布。
- 问题明细必须按架构、测试、安全和质量分类展示。
- 时间线显示事件顺序、Agent、事件类型和时间。
- 分析完成后可查看和下载 Markdown 报告。
- 下载响应必须使用附件头和安全的 Markdown 文件名。
- 报告必须包含可显示的严重级别和分类图片，并提供自包含 HTML 版本。

### FR-07 数据持久化

- PostgreSQL 保存仓库、分析、事件、问题和产物元数据。
- LangGraph checkpoint 保存图执行状态。
- 报告、问题 JSON 和仓库快照保存到分析工作区。
- 数据库不可用时应返回受控错误，不得静默伪造结果。

### FR-08 外部模型

- 支持 OpenAI 兼容的 Chat API。
- 支持 DeepSeek 或 DashScope 配置切换。
- 模型输出必须校验 JSON Schema。
- 模型不可用时任务应失败，不能使用固定内容冒充真实分析。

### FR-09 MCP 工具

- MCP 使用 Streamable HTTP，并挂载到 FastAPI。
- 提供目录、文件、代码搜索、相关测试和确定性规则五类只读工具。
- Agent 只能调用分配给自己的工具。
- 工具路径必须限制在对应分析工作区。
- 工具返回内容必须脱敏并限制大小。
- 工具调用、耗时和失败状态必须持久化并实时显示。
- 单个 Agent 默认最多调用 3 次工具。
- 不提供 Shell、网络请求、代码执行和仓库写入工具。

## 7. 数据与知识图谱要求

### PostgreSQL

- 关系型业务数据、状态、事件、问题和报告均以 PostgreSQL 为准。
- 不允许在 Milvus 中保存事务型状态。

### Milvus

- 用作代码块和文档片段的向量检索。
- Embedding 维度必须与集合配置一致。
- 当前版本完成连接和健康检查，分析主链路写入与检索仍属于后续阶段。

### Neo4j

- 目标模型为 Repository、File、Class、Method、Test 及依赖关系。
- 当前版本完成驱动、连接和约束基础，分析主链路自动建图仍属于后续阶段。

## 8. 非功能需求

### 安全

- 不执行被审查仓库内容。
- 不在日志、报告、错误响应和版本控制中泄露密钥。
- 限制可克隆主机、下载大小、文件数量和执行时间。
- 私有仓库功能启用前必须增加凭据托管和权限隔离。

### 性能与稳定性

- 默认克隆超时 180 秒。
- 默认仓库体积上限 200 MB。
- 默认最大文件数 10,000。
- 默认读取最多 80 个源码或配置文件的摘要。
- 默认单文件最多读取 20,000 字符。
- SSE 空闲时每秒检查一次新事件，不进行高频页面轮询。

### 可维护性

- Python 使用模块化分层，类型检查启用严格函数签名。
- 前端使用 React + TypeScript，生产构建必须通过类型检查。
- 项目文档、提示词和界面默认使用中文。
- 依赖、环境变量、数据模型和架构变更必须同步更新文档。

## 9. MVP 验收标准

以下条件全部满足才可标记为 MVP 验收通过：

1. Ruff、mypy、pytest 和前端生产构建全部通过。
2. 使用一个公开 Spring Boot 仓库完成真实克隆、扫描和分析。
3. 六个专业 Agent 均产生真实执行事件，主 Agent 最终进入完成状态。
4. 至少一条确定性问题写入 PostgreSQL，并可从 API 和前端查看。
5. SSE 能显示新增事件，页面耗时会更新。
6. 取消中的任务最终为 `cancelled`，不会继续写入完成报告。
7. 非白名单主机和非法 URL 被拒绝。
8. 报告包含仓库、分支、Commit、问题证据和服务建议，并可下载。
9. 项目文档与实际代码、配置和实现状态一致。
10. Git 工作区不包含 `.env`、真实密钥、前端依赖目录或构建产物。
11. MCP Streamable HTTP 能完成真实握手和工具调用，Agent 时间线出现工具事件。

## 10. 后续阶段

- 将扫描后的代码块写入 Milvus，并在架构和质量分析前执行相似代码检索。
- 将文件、类、方法和依赖写入 Neo4j，并展示可交互依赖图。
- 增加 Java 语法树和 Maven 依赖解析。
- 增加分析结果对比、增量扫描和仓库基线。
- 增加私有仓库、认证、组织隔离与任务并发控制。
