# 前端控制台

更新时间：2026-11-03

## 1. 设计方向

前端采用偏编辑设计和技术工作台的视觉语言：

- 浅灰网格背景与高对比黑色排版。
- 荧光绿作为运行中和关键数字的强调色。
- 等宽字体显示 URL、Commit、事件类型和文件位置。
- 左右分栏：左侧创建与仓库历史，右侧展示当前分析。
- 桌面端顶部栏固定，左侧仓库栏和右侧工作区独立滚动，页面本身不上下移动。
- 移动端左右栏上下堆叠，恢复整页滚动。
- 问题卡片按严重级别使用颜色边界，强调证据和修复建议。
- 无大型 UI 框架，减少体积并保持视觉一致。

界面默认中文，代码字段、事件类型和环境变量保留英文。

## 3. 启动

同时启动前后端：

```powershell
cd E:\Aipracite\py_workspace\Multiagent
python dev.py
```

打开 `http://127.0.0.1:5173`。按 `Ctrl+C` 会同时停止 Vite 和 FastAPI。

`dev.py` 会在控制台用中文依次显示 Python/Node 环境检查、FastAPI、MCP、React、健康检查和最终访问地址，并在退出时显示服务关闭过程。前端固定使用 5173 端口，端口被占用时会给出明确错误。

单独启动：

```powershell
cd frontend
npm run dev
```

生产构建：

```powershell
cd frontend
npm run build
```

构建产物写入 `frontend/dist/`，该目录不提交 Git。

## 4. 页面能力

### 新建分析

- 输入公开 Git URL。
- 可选指定分支。
- 校验失败时展示后端返回的中文错误。
- 创建成功后立即开始分析并进入实时视图。

### 仓库与历史

- 左侧显示提交过的仓库。
- 首次进入页面只加载仓库列表，不自动恢复最后一次分析结果；用户选择仓库后才加载其最新分析。
- 选择仓库后加载分析历史。
- 点击历史运行恢复状态、事件、问题和报告。
- 支持对同一仓库重新分析。

### 状态概览

- 分析状态。
- 当前 Agent。
- 失败原因：优先显示后端保存的真实错误，不再只显示通用提示。
- 实时运行耗时。
- 问题数量。
- Commit 和分支。
- PostgreSQL、checkpoint、Milvus、Neo4j、LLM 和 Embedding 状态。

### Agent 进度

展示主 Agent、Repository、Architecture、Test、Security、Quality 和 Report。事件完成后更新节点状态。

### 问题列表

- 按 critical、major、minor、info 统计和筛选。
- 使用环形图展示严重级别分布。
- 使用分类条形图展示架构、测试、安全、质量的占比。
- 点击分类条形图可以筛选对应问题。
- 问题按架构、测试、安全、质量分组列出。
- 展示分类、文件与行号、标题、证据、影响和建议。

### 时间线

- 按事件序号展示真实运行事件。
- 显示相对开始时间、Agent、事件类型和中文消息。
- 展示 `tool.started`、`tool.completed` 和 `tool.failed` MCP 工具事件。
- 事件时间使用后端保存的 UTC 时间计算，不执行数据库服务器时间。
- 使用 SSE 增量更新，不进行高频状态轮询。

### 详细执行过程

时间线页提供“详细执行过程”开关，默认关闭。开启后按 Agent 分组展示：

- Agent 状态和耗时。
- 主 Agent 路由事件。
- 每个 MCP 工具的名称、调用时间和耗时。
- 工具参数、结果预览或错误类型。
- Agent 开始、完成和失败消息。

详情组件只展示可观测事件，不展示模型隐藏推理。当前运行或失败 Agent 默认展开，其他 Agent 可以单独展开或收起。

### 报告

- 通过内嵌 HTML 在线查看带图表的完整报告。
- 分析完成后，页面顶部和报告页分别提供“下载 Markdown”和“下载 HTML”按钮。
- 优先下载自包含 HTML 报告，图片直接嵌入文件，无需额外资源。
- 仍可单独下载包含内嵌 SVG 图片的 Markdown 报告。
- 下载接口返回 `Content-Disposition: attachment`，文件名为 `仓库名-分析ID-report.html` 或 `.md`。
- 文件名只保留安全字符，报告文件必须位于对应分析工作区。
- 分析失败或取消时不提供成功报告。

### Ask AI 证据问答

- 只有分析状态为 `completed` 时才允许提问。
- 首次提问会创建绑定当前仓库和分析的聊天会话。
- 页面显示用户消息、助手生成状态、最终中文回答和 Finding 引用卡片。
- 引用卡片显示文件、行号和脱敏后的证据摘要。
- 同一回答生成期间禁用发送按钮，后端也拒绝同一会话的并发提问。
- 聊天事件按真实 Agent 顺序显示 Intent、Conversation 和 Evidence Verifier 状态。
- 聊天 SSE 使用 `after_sequence` 游标，连续提问时只接收新一轮事件，不重放旧轮次。
- “Ask AI”回答只使用已有分析 Finding，不会声称执行了目标仓库代码、测试或构建。

## 5. API 连接

开发模式默认请求当前主机的 `8000` 端口。可以通过 Vite 环境变量覆盖：

```dotenv
VITE_API_BASE_URL=http://127.0.0.1:8000
```

后端允许的来源由 `FRONTEND_ORIGIN` 控制：

```dotenv
FRONTEND_ORIGIN=http://localhost:5173,http://127.0.0.1:5173
```

## 6. 日志与停止

`.env` 默认关闭逐请求访问日志：

```dotenv
UVICORN_ACCESS_LOG=false
```

应用启动、异常和关键服务状态仍会输出；`httpx` 和 `httpcore` 的逐请求信息被降到警告级别。页面上的“停止”按钮只取消当前分析，不会退出服务。

## 7. 当前限制

- Markdown 报告以 `<pre>` 展示，尚未接入 Markdown 渲染和代码高亮。
- 尚未实现 Neo4j 依赖图可视化和 Milvus 相似片段面板。
- 聊天尚未按需将仓库代码写入 Milvus，也不能直接回答“某个未出现在 Finding 中的函数如何实现”这类需要额外源码检索的问题。
- 尚未展示历史聊天会话列表；当前页面在切换仓库或分析后会创建新的分析级会话。
- 尚未实现登录、多用户和仓库权限隔离。
- 当前轮询间隔由后端 SSE 实现控制，前端不使用 WebSocket。
